# 本地匹配与证据边界

Studio 的输出核心是分段时间映射：参考时间映射到原片时间。XML 解析、映射、弹幕投影和导出独立于 React；原始素材不被修改。

## 音频与画面

AAP 是尝试性实现，目前只有自动化和合成样本检查，尚未经过实际使用测试。这里保留实现原理和局限，供后续 fork 验证和改进，不将其视为已经实用验证的匹配方案。

音频路线保留现有粗检索、精对齐和逐段证据流程。AAP 是独立画面入口，复用媒体身份校验、工具链固定、进程监督、取消和项目时间图，不冒用音频验证证据。

AAP v1 使用 FFmpeg 按展示时间归一化到 4 fps、32×32 灰度帧，计算低频 8×8 DCT，去掉 DC 并以中位数生成二进制 pHash。亮度方差过低的帧不作为锚点。四个 16-bit 索引分区进行半径 2 查询，再检查完整哈希的 Hamming 距离；候选过多时拒绝猜测。时间上明显不同且分数接近的位置视为歧义。

唯一候选经单调路径筛选，在时间空洞或持续偏移变化处分段，每段至少八个锚点。首版接受的段内速度范围为 0.8–1.25；不跨越长无证据区，不向首尾未观察内容外推。没有证据说明两侧缺口的具体性质时保留 ambiguous；不会将弹幕套到最近一帧。

采样格使用 FFmpeg fps 过滤器的展示时间语义，不使用原视频帧号除以名义帧率。格点不是原始帧精确 PTS；当前保守记录至少 500 ms 的边界不确定度。此版本尚无独立实媒体准确率校准，画面候选需要检查，不自动签发 verified。

## 资源与限制

- 单文件最多 6 小时，最多 86,400 个采样帧；原始采样字节有上限。
- 指纹缓存仅在进程内保留四份，以文件完整身份、视频流、时间原点、特征版本与工具链身份为键。
- UI 将最多 64 个组合顺序提交；已有音频批次合同保持独立。
- 不承诺处理大幅裁切、重绘、强遮挡或镜头乱序；重复镜头可能降低召回。
- 当前拒绝负展示偏移，明确报错；未来若扩大时间轴支持范围，需要额外样本与回归。

## 可复现检查

`scripts/verify-visual-aap.py` 生成自己的无音轨视频，插入黑屏、删除片段、改变亮度并有损转码，然后调用生产 headless 入口。脚本检查至少三段关系、填充没有被投影、已匹配区间误差和视觉证据类型。它不是实媒体基准，也不能用来宣传 SOTA 或任意影片的准确率。

前端回归使用该脚本实际生成的提案，验证合同、项目保存恢复、弹幕投影与导出 XML 重解析；原生测试另检查重复片段、黑屏、亮度变化、局部变速和取消。

方向参考：[bili-danmaku-mapper 的 AAP](https://github.com/dowdah/bili-danmaku-mapper/blob/184d97ad6024bf72b59ac55c07146c8a4d444211/mapper_frame.py)；时间采样语义参考 [FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html#fps)。代码为独立实现，未复制其按最近有效帧回填弹幕的行为。
